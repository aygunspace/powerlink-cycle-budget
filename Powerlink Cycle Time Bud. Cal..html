Method, assumptions and limitations — read before quoting a number

Frame timing. Standard Fast Ethernet at 100 Mbit/s, so 0.08 µs per byte. Each frame on the wire costs 38 + payload bytes: 7 preamble + 1 SFD + 14 MAC header + 4 FCS + 12 inter-frame gap. The POWERLINK header is taken as 24 bytes inside the Ethernet payload, and the payload is floored at the 46-byte Ethernet minimum — which is why a frame carrying no process data still costs 6.72 µs.

Cycle structure. SoC, then the isochronous phase (PReq to each polled CN and its PRes back), then SoA opening the asynchronous phase and one ASnd frame, then idle until the next SoC. Multiplexed nodes are counted as ceil(n / spread) polled per cycle. With Poll Response Chaining the individual PReq per chained node is dropped and only the chained PRes is counted.

Infrastructure delay. Each frame is charged hop count × per-device delay. The defaults follow the figures used in the POWERLINK specification's own performance examples: 0.5 µs for a hub, around 5 µs for a cut-through switch and upwards of 10 µs for store-and-forward. This is the single most commonly underestimated term in a POWERLINK budget — see the comparison above.

Node turnaround is hardware-dependent and is NOT taken from any vendor's data sheet. It is a parameter you must set from your own devices. The default of 1 µs is a placeholder for sanity-checking, not a specification. Everything downstream of it inherits its error.

What this is not. A first-order budget for feasibility screening and for reasoning about where the time goes — not a configuration result. The authoritative figure for a real network comes from the engineering tool that configures it, against the actual device description files. Not modelled: per-device internal latency differences, PRes timeout and error handling, hot-plugging, redundancy, SoA/ASnd scheduling policy across cycles, cross-traffic, cable propagation (negligible at these distances), or any behaviour specific to a particular manufacturer's implementation. The protocol supports up to 240 nodes in one network; the arithmetic here does not enforce any other vendor-specific limit.

Why this exists. "How can I calculate the POWERLINK cycle time?" is a standing question for anyone sizing a network, and the public answer is usually qualitative — it depends on data volume, node count and polling frequency. That is true, but it is not a number you can put in front of a customer. This is an attempt at the arithmetic, in the open, with every assumption visible and arguable.
